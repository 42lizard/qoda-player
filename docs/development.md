# Running the first application slice

This is development software, tracked in [issue 21](https://github.com/42lizard/qoda-player/issues/21). It contains a real Rust process, Plex provider, embedded libmpv owner and standalone Quickshell window. It does not install a service or modify Omarchy configuration.

## Requirements

Rust/Cargo 1.99 or newer, libmpv development/runtime libraries (tested with mpv 0.41), Quickshell (tested with 0.3.2), Qt Quick Controls, SQLite and ALSA development libraries (`alsa-lib` on Arch) and pkg-config, a running PipeWire desktop session, and Brave for the sign-in button. TLS certificate verification stays enabled. The launcher requires Python 3. Desktop media controls use the current user session D-Bus; an unavailable bus leaves core playback/UI operation available. The automated QML checks require Qt 6 Quick Test (`/usr/lib/qt6/bin/qmltestrunner`, provided by `qt6-declarative` on Arch); an older Qt 5 runner is not used. Automated audio capture tests also require `/usr/bin/ffmpeg` to generate lossless FLAC fixtures. Automated MPRIS tests require `/usr/bin/dbus-daemon` and never use desktop service activation. Saved sign-in requires `/usr/bin/secret-tool` (libsecret) and a desktop Secret Service. The optional local validation-login import also requires its specific existing keyring item.

## Start and stop

From the repository:

```sh
./tools/dev.py
```

Select **Connect Plex**, open the browser sign-in, authorize Qoda, then choose a library in the left sidebar. **Menu → Account** exposes sign-in saving, restoration and disconnect controls. The **Search** navigation entry searches tracks across libraries with explicit library/server labels and partial-source status; see [search scope and limits](search.md). The initial **Albums** view searches album titles in the selected library. **Tracks** retains track browsing/search: browse pages contain at most 100 tracks; track search returns up to 100 matches. **Play now** replaces the listening session with the selected track and starts it. The bottom transport controls playback; its position slider supports mouse and keyboard seeking once current playback and duration are confirmed. Play retries a stopped selected track or starts pending content after completion; Replay restarts a retained exhausted selection.

The right queue stays visible from 1100 logical pixels wide. In narrower windows, **Queue** opens a modal drawer without replacing the browser or its search/scroll state. Close, Escape or an outside click dismisses it. **Menu** also contains cache settings, the session gapless toggle, Hide and explicit Quit. Compact opens the separate overlay. Save and desktop-control failures keep their recovery actions visible.

`python tools/check-layout.py --output /tmp/qoda-layout` renders the production full window at wide, narrow and small sizes with fictional data and verifies the drawer and retained state. It runs offscreen without a backend, Plex, credentials, audio or compositor changes. Test-only resize/capture hooks and a compact-surface stub exist only in a temporary UI copy; compact layer-shell behavior still requires the native surface checks. The script requires Quickshell and Qt's offscreen/software platform, and writes PNGs only when `--output` is given.

### Track selection and bulk actions

In **Tracks**, click a title to select one row, Ctrl-click to toggle rows, or Shift-click to select a range from the anchor. Ctrl+Shift adds a range to the existing selection. Checkboxes offer the same independent selection with mouse or keyboard; selecting a row never starts playback. **Select page** selects at most the 100 loaded rows. The last clicked track still seeds the existing new-playlist action.

**Play selected** replaces the listening session and starts the selected tracks. **Play selected next** schedules them after existing FIFO Play next requests; **+ Queue selected** appends them. Each batch uses displayed page order, preserves independent duplicates across separate additions, and is applied completely or rejected without partial queue changes. Adding or scheduling tracks preserves playback intent. The 500-occurrence queue limit still applies. These actions change the local queue, not a saved Plex playlist.

Selection clears when the page, library, account or search context changes; it survives full/compact/hidden form changes within the UI session. Buttons remain disabled while a page is loading or the visible search/library no longer matches it. Requests carry account, catalog-page and queue revision fences, all as decimal strings. The backend resolves source-scoped references against the current page and ignores client-supplied metadata. Missing, duplicated, cross-source, stale or oversized selections are rejected as a whole. Browsing removes the old track page immediately, so a failed replacement request cannot leave actionable rows from an earlier context.

### Albums and covers

The **Albums** tab lists up to 100 albums per page with Previous/Next pagination. Search filters album titles within the chosen library, or within the current artist when an artist page is open. Open an album to see its cover and disc/track-ordered contents, or choose **Back to albums** to retain the loaded page. Grid cards load thumbnails for visible albums. The detail cover loads when an album is opened. Wide windows keep the queue beside the browser. In narrow tiled windows, **Queue** switches to queue controls and **Browser** returns to the current album; header and playback controls wrap to fit.

**Play album** replaces the listening session with a complete ordered copy. **Play from here** copies the chosen track and those after it. **+ Queue** appends the album or individual track without selecting or starting audio; **Next** schedules an individual track with the queue's normal FIFO rules. Album and track actions use source-scoped identities and the current loaded snapshot revision; paging, changing libraries or signing out invalidates the old detail. Queue occurrences remain independent of later library changes.

Opening an album requires matching library metadata and all its tracks in a complete response, with a maximum of 500 tracks. Mixed-parent, duplicate-key, wrong-library and partial responses are rejected, rather than partly queued. Disc and track numbers order multi-disc albums. This does not qualify every multi-disc/server variant.

The Rust provider requests a 320-pixel JPEG from Plex's authenticated image endpoint, using only the selected album's own numeric thumb path. It refuses arbitrary URLs, redirects, token query parameters, non-JPEG responses, payloads above 256 KiB and JPEG dimensions above 512 pixels. Both grid and detail covers use backend-issued, revocable local image URLs backed by the same memory/disk cache. Album metadata requests do not fetch artwork. Missing, denied, oversized or malformed covers use a placeholder and leave album tracks usable; no upstream artwork URL or token enters QML. Detail images load only while the album detail is visible, and QML's own image caching stays disabled. There is no automatic library-wide cover download.

Album listing, children and image endpoint behavior follows the [Plex Media Server API](https://developer.plex.tv/pms/). Requests are cancellable and fenced by account/request generations, so a slow cover read cannot restore a previous account's detail after sign-out. Loading a cover never starts media playback.

### Persistent artwork cache

Visible grid covers are cached on demand as private JPEG files in `$XDG_CACHE_HOME/qoda/artwork-v1` (default `~/.cache/qoda/artwork-v1`). The default disk target is 1024 MiB; **Cache** in the header shows usage and changes the target from 0 to 4096 MiB. Zero disables disk caching while keeping the bounded memory cache. The target is saved in `$XDG_CONFIG_HOME/qoda/cache-settings/artwork.json`, independently of the listening session and disposable images. Cache clearing and sign-out retain this preference. The cache holds JPEG payloads and cache preferences, with no separate catalog records or authentication metadata. Filenames hash the source-scoped album reference. Plex source identities already include the account, server and library.

Freshness is seven days from download. Reading an image updates its access time for eviction without extending freshness. A stale hit displays immediately and starts a bounded background provider refresh; a successful refresh replaces the local URL so QML cannot keep an old image indefinitely under the same identity. Temporary network failures retain stale bytes and suppress repeated refresh requests for 30 seconds. A denied artwork request removes that cached image and replaces its grant with a negative result; it is not treated as proof that the entire library was revoked. Paging/library changes revoke grants without deleting useful cached images. Cache access requires a newly published grant from the active, authenticated provider and current catalog page; this does not enable offline library browsing.

The cache also bounds bookkeeping to 8192 files, each at most 256 KiB with JPEG dimensions of 1–512 pixels. The 64-entry/16 MiB memory limit, two active upstream reads and 32 pending HTTP requests remain. Least-recently-used files are evicted to meet the configured target; filesystem overhead is outside that managed target. A single bounded worker owns disk I/O, with a profile lock preventing competing writers. Private directories/files, no-follow opens, hard-link rejection, bounded reads and opened-directory identity protect filesystem access. Malformed JPEG headers, oversized payloads and unsupported dimensions are discarded; QML performs actual decoding. Unsupported settings are preserved and exposed as unavailable. Cache failure leaves provider-backed browsing available and remains visible until recovery succeeds.

**Clear artwork** preserves the queue, sign-in and target, revokes old URLs and cancels old fetches. Visible covers are then fetched again. Disconnect and **Sign out & forget** additionally purge cached images. Epoch fences reject queued and late writes from before a purge. A synced purge-pending preference is written before deletion; restart completes interrupted cleanup before cache reuse. Failed cleanup is visible with **Retry cleanup**, and disk reads/writes remain blocked while it is pending. Cache controls run asynchronously so they do not block transport; disconnect sends Pause/Stop before filesystem cleanup. No artwork cache or preference files are included in session backups.

Grid and album-detail covers share the same cached JPEGs, freshness, budgets and sign-out cleanup. Comprehensive library-wide access-loss invalidation remains separate work. Catalog metadata caching and its current offline limits are described below. A cache hit is not proof of current server access beyond the provider/catalog context that granted it.

### Persistent catalog metadata

Track, album and artist **pages**, plus previously opened album-detail snapshots, use a separate disposable SQLite database at `$XDG_CACHE_HOME/qoda/catalog-v1/catalog.sqlite3`, defaulting to `~/.cache/qoda/catalog-v1/catalog.sqlite3`. **Cache** exposes a persistent metadata target of 256 MiB by default, adjustable from 0 to 1024 MiB. Zero disables disk metadata caching and evicts its contents. Preferences and the interrupted-purge marker live in `$XDG_CONFIG_HOME/qoda/cache-settings/catalog.json`; clearing metadata keeps the target, artwork cache, sign-in and listening session. Metadata is not included in durable-session backups.

Freshness is 15 minutes from a successful provider read, not from the last cache access. Fresh cached pages can avoid a repeated server catalog request. Stale pages display immediately while a bounded live refresh runs. Track searches can immediately show matches from the source's cached-track index while asking the provider; these results use literal Unicode-lowercase matching and are always labelled **cached tracks only / incomplete**, with at most 100 matches. They do not reproduce Plex relevance or promise that the entire library has been searched. Cached exact-query pages and cached index search are distinguished from live results. A temporary refresh failure retains valid cached results with explicit stale/incomplete provenance.

The active provider's discovered library allowlist is checked before any cache read. Source identities retain account/server/library scope, and request keys include page kind, offset, query, optional artist identity or the exact source-scoped album reference. Cached payloads are typed, bounded and revalidated against that request. A denied or unknown-source response clears the current denied view and purges that source's persisted pages/index; it does not fall back to cached results for that denial. This is request/cache invalidation, not a claim that every library-wide permission change, artwork copy or queue-history reference is comprehensively reconciled.

Each displayed Tracks snapshot has a lossless page revision separate from the browse-request generation. A fresh response with identical contents retains selection; changed contents invalidate it and reject old bulk commands. Cached page display and live refresh retain the existing account/request fences. Album-detail snapshots store the album, complete ordered tracks and provider revision, with up to 500 tracks; embedded cover images are removed before persistence. Opening an album displays any cached details immediately and always starts a live refresh, even within the page freshness window. Cached details are labelled explicitly and remain readable after a temporary refresh failure. **Refresh album** retries without starting playback. Album/track queue actions remain disabled and are rejected by the backend until the current detail has refreshed successfully; a changed provider revision rejects commands from the previous snapshot. Denial removes the cached source and displayed details. Prepared media, credentials, temporary stream access and saved playlist writes are excluded from this cache. Playing a cached track still prepares current access/version information through the provider and never treats metadata as proof of stream availability.

The worker bounds records to 4096 pages and 50,000 indexed tracks; each encoded record is limited to 3 MiB, with lists capped at 100 entries and album details at 500 tracks. Detail snapshots count toward the page budget and do not add entries to the cached-track search index. An access counter drives least-recently-used eviction without extending freshness. Eviction batches and source purges reclaim disposable space with incremental vacuum; the target accounts for serialized metadata/index fields, excluding SQLite/filesystem overhead. A profile lock prevents competing writers. SQLite uses a private no-follow database, checked directory/database identities, secure deletion and a separate application/schema identity. Damaged disposable databases can be rebuilt with cached coverage reset; foreign or newer databases/settings are preserved and reported unavailable. Cache failure falls back to provider access rather than changing the saved queue.

**Clear metadata** resets loaded browser views, cancels their pending reads, and fences queued/late cache writes before deleting/recreating only the disposable metadata database. Browse again to load pages afterward. Cache controls run asynchronously. Explicit disconnect/sign-out purges both metadata and artwork, with durable pending markers and visible retry controls for incomplete cleanup. General cache targets and the durable-session storage remain separate.

This increment supports cached pages and cached-track search for sources discovered in the **current connection**. It does not yet provide offline startup/library discovery, cached playlist editing or offline music downloads. The cached catalog is always partial unless a separate complete-sync feature establishes otherwise; none is implemented here.

### Compact player

Choose **Compact** in the browser header for a small bottom-right overlay on the invoking monitor. **Expand** returns to the existing browser; forms remain alive, preserving the page, query, selection and scroll position within the UI session. **Queue** expands to queue controls. **Hide**, native browser close and compact Escape hide the interface while the backend keeps its listening session. Show/toggle restores the last visible form; a UI restart starts in the browser. Explicit **Quit** stops the backend and UI.

The panel shares the coordinator's transport and nominal-presentation view with MPRIS, even when D-Bus is unavailable. Confirmed metadata/position use the same clock, generation and failure guards. A selected or restored occurrence without those witnesses is labelled **Selected · playback unconfirmed**, with no invented playback position. Resume/Pause, Previous and Next use backend capabilities and queue fences. Playback errors, buffered-transition review and failed storage checkpoints remain visible; Expand opens the full controls.

The overlay reserves no desktop space. Passive preview takes no keyboard focus; interactive invocation primes focus briefly and settles to on-demand focus. Hiding releases it. Placement captures the focused Hyprland monitor at invocation, with the first screen as fallback. Ctrl+K focuses search (expanding the compact view first); Space toggles playback after child controls have had a chance to consume it. Compact Escape hides; full-browser Escape leaves it open. Native physical-key dispatch, multi-monitor/hotplug behavior and focus return still require the separate hands-on acceptance work. No global bindings or desktop services are installed.

Application IPC is available through `quickshell ipc --path ./ui call -- control METHOD`: `show`, `hide`, `toggle`, `showFull`, `showCompact` and `previewCompact` (passive). Existing browse/queue IPC opens the full form. Commands address this UI path rather than other Quickshell instances.

After building the backend, `python tools/check-surfaces.py` runs the native surface/MPRIS checks in an empty private runtime/config/state directory. It requires the current Wayland session, Quickshell, `busctl` and an unused Qoda MPRIS name. It verifies passive/interactive compact mapping, hide/show/toggle/last-form restoration, rapid switching, retained empty-browser state, nominal unknown startup, hidden MPRIS controls, Quit and paused restart. It reads no credentials, connects to no provider, plays no music and cleans up its processes. It does not inject physical keys or qualify real-device output. A development screenshot of the empty panel was also inspected at the current output scale.

### Desktop media controls (MPRIS)

The backend owns `org.mpris.MediaPlayer2.qoda` on the current user's session bus, at `/org/mpris/MediaPlayer2`. MPRIS-compatible desktop clients can control it while the QML window is hidden or restarting. Commands enter the same serialized coordinator as UI commands; MPRIS does not own another queue or libmpv instance. Current methods include Play, Pause, PlayPause, Stop, Next, Previous, relative Seek, occurrence-checked SetPosition and Quit. LoopStatus maps None/Track/Playlist to Repeat Off/One/All; Shuffle and repeat changes remain explicit preferences and never start playback by themselves.

Stop retains the queue and selected occurrence, resets its local position to zero and cancels pending preparation/media access. Play can then restart the selection from its beginning. It does not clear queue membership. Immediate Play after Stop reloads the retained selection even if libmpv has not yet reported its asynchronous stop; repeated Play during preparation waits for that preparation rather than loading it again. Next/Previous preserve paused intent, and seeking clamps negative offsets to the start; relative seeks beyond a known length advance to Next. Negative/out-of-range SetPosition calls and mismatched occurrence IDs have no effect. Desktop track paths contain both session and occurrence identities, so duplicates and session replacement cannot reuse a stale seek target. Commands abandoned or expired before coordinator processing are discarded.

Desktop metadata follows confirmed nominal playback evidence, rather than preparation or saved recovery data. Until the selected render attempt has usable clock evidence, PlaybackStatus is Stopped, metadata is empty, Position is zero and CanSeek/CanGoPrevious are false. Play and Pause can still control pending intent where content is available. Once confirmed, title, artist, album, optional length and the occurrence path are exposed; known pauses freeze the last nominal position. A stale generation, missing active clock, stalled positive timestamp, stop, error, disconnect or seek/rebuild invalidates current metadata. While progress is expected, a timestamp that has not changed for more than 250 ms becomes unknown at the next existing 250 ms coordinator sample; known pause freezes remain valid. This projection does not add the full playback adapter stall/recovery watchdog. This is a conservative development projection, not a hardware/audibility clock. Seeked is emitted after a matching nominal clock is observed for an accepted seek; a paused seek can remain unconfirmed until playback resumes, and an obsolete render attempt cannot emit a late seek signal. Position ticks do not emit PropertiesChanged.

This increment leaves player volume at unity and rate at 1.0. Other Volume/Rate values return NotSupported; use the system output mixer for volume. No gain or fidelity guarantee follows from MPRIS. OpenUri is unsupported: desktop clients cannot bypass provider browsing with arbitrary URLs or local files. CanRaise and HasTrackList are false; the service does not start a UI, provide desktop artwork, export queue editing or claim an installed desktop entry. Quit requests backend shutdown and notifies the connected QML shell to exit. Physical media-key bindings and desktop installation are not changed here.

If the session bus is unavailable or another instance owns Qoda's bus name, playback/UI operation continues with a visible media-control availability message. The backend does not replace another owner or queue for its name. A lost bus connection disables the projection and exposes **Retry desktop controls**. Retry starts one asynchronous connection attempt with a three-second timeout, leaving Qoda transport controls usable; repeated requests while connecting are ignored. Successful reconnection publishes the coordinator's current nominal state without restarting the backend or changing its queue/playback intent. Another bus owner is never replaced. Old connection notifications and queued commands carry connection identities, so they cannot control or disconnect a replacement. Quit cancels pending attempts and releases completed-but-uninstalled connections. No D-Bus activation file is installed. Each desktop command has a three-second acknowledgement deadline, and capability checks are resolved again against current coordinator state.

Inspect only Qoda with an existing client, for example `busctl --user get-property org.mpris.MediaPlayer2.qoda /org/mpris/MediaPlayer2 org.mpris.MediaPlayer2.Player PlaybackStatus`. An installed `playerctl` can target `--player=qoda`; it is optional and is not installed by this repository. Core method/property behavior follows the [MPRIS Player specification](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html).

### Artists and thumbnail loading

The **Artists** tab lists up to 100 artists per page and searches artist names within the selected music library. Open an artist to browse their albums, or select the artist button in an album detail. Artist identity includes the library and Plex key; identical display names are not merged. Artist album pages keep that identity during pagination and album-title search. **All albums** clears the artist filter. Track, album and artist searches retain separate text while switching tabs. Changing libraries or disconnecting clears the old browser context; late reads cannot restore it.

An album page publishes up to 100 unguessable local thumbnail URLs without fetching images. QML requests covers only for grid cards intersecting the visible viewport. Hidden windows, the queue view and album details do not start grid image loads. Opening an album publishes the selected detail cover through the same cache and validation path. Thumbnail traffic uses a dedicated IPv4 loopback listener with exact Host checks, no redirects and no upstream URLs or credentials exposed to QML. Each request resolves only a backend-issued album reference, loads authenticated album metadata and reuses the same JPEG validation as the detail cover; it does not fetch tracks or audio.

Thumbnail provider jobs run at most two at a time, with at most 32 HTTP requests admitted and a 25-second request deadline. A memory LRU retains at most 64 entries, each capped at 256 KiB (at most 16 MiB of cached JPEG bytes). Successful entries expire after five minutes and failures after 30 seconds. Cache-Control is `no-store`; decoded image caching is disabled in QML. Paging/searching issues new URLs and cancels obsolete in-flight thumbnail work; a completed cached cover may be reused by source-scoped album identity. Disconnect/sign-out clears the memory cache and grants. Old URLs return 404, and a cancelled download cannot repopulate the cache. Bytes already delivered cannot be retracted.

A missing or failed image keeps a placeholder. Revisiting a card or reloading a page can request it again; there is no push invalidation for artwork replaced on Plex, and an already displayed image may remain until revisited. Disk caching, conditional revalidation, artist artwork and broader context navigation remain later work.

MPRIS **Raise** asks an attached Qoda UI to restore its last full/compact form interactively. **CanRaise** follows explicit shell connections; ordinary IPC clients do not advertise a UI. A disconnected/headless backend reports false and does not launch a new UI. Property changes are emitted on the root MPRIS interface, as required by the [MPRIS root specification](https://specifications.freedesktop.org/mpris/latest/Media_Player.html). Raise changes visibility only, with no transport or queue mutation. Requests use opaque one-shot tokens; the UI ignores existing tokens on its first snapshot or reconnect, preventing old requests from being replayed. Focus remains subject to the compositor.

### Queue controls

**+ Queue** appends without starting or resuming audio. **Next** on a catalog row schedules the track after earlier pending Play next additions; with no selection it schedules at the front without autoplay. Duplicate tracks remain distinct occurrences. The side panel shows the selected occurrence and upcoming entries. **Play** on a queue row explicitly starts that occurrence and continues through the remaining queue.

Use the arrow buttons to reorder upcoming entries; the selected entry is pinned. Removing an upcoming occurrence leaves playback alone. Removing the selected occurrence selects/prepares its successor while preserving playing versus paused intent, or stops if none remains. **Next track** also preserves paused intent. **Clear upcoming** retains the selected entry and traversed membership; **Stop & clear** cancels preparation, stops audio and discards the session.

A matched native EOF plus an idle engine advances to the next playable entry. Known individual failures are skipped while their identities remain inspectable. Observed network interruptions of the current pinned stream use [bounded recovery](audio/stream-recovery.md), preserving occurrence, nominal position and prior pause intent. Other engine/server failures stop for explicit retry; the app does not infer successful completion from arbitrary idle/Stop events. Natural EOF is a nominal engine result, not physical-output proof or a guarantee that a damaged source was complete. No Plex listening reports are sent. At exhaustion, the session remains available for explicit **Replay**, which starts from the retained session's beginning. Adding content afterward remains stopped until Play/Resume is chosen.

Edits carry the session ID and queue revision. A stale edit is rejected with the latest state; the UI never silently applies an outdated row index. Navigation also advances this revision. Queue rows identify engine selection, not a physical presentation clock. Gapless mode can preload one upcoming track; its selection and nominal presentation remain separate, as described below. Very long display fields are bounded to 1024 UTF-8 bytes; identities are validated rather than truncated.

The current bound is 500 occurrences in retained session membership. Traversed entries remain in the replay set, but are not presented as listening history. The queue survives hide, reload, UI process restart and backend restart through SQLite checkpoints. Restoration stays paused and does not unlock the keyring. Disconnect/sign-out discards the saved session and its backups. The **Unavailable** tab retains individual missing, unsupported-media and changed-version failures per occurrence, including traversed entries. Natural automatic progression skips those entries without inventing listening credit. A scan can try each of the at most 500 occurrences once before stopping when none is playable, including Repeat One/All. Network, sign-in, access-denied, unknown-library and malformed-reply failures pause at the selected occurrence rather than consuming the library. A paused or explicitly selected preparation failure is marked and stays selected; it does not silently advance. **Retry** explicitly prepares that same occurrence/version again; Resume (including desktop Play) at an exhausted all-unavailable session explicitly retries its retained selected failure. The tab badge shows the retained failure count. **Skip & continue** explicitly starts the next playable entry. Ordinary Next preserves paused intent. Removing an unavailable occurrence deletes only that occurrence. Known individual failures remain until successful preparation or explicit removal; they may be stale, so use Retry after access/content changes. Prepared-version mismatch never silently selects a replacement version; browse and Play now as new content to accept a different version. A complete listening-history archive and bounded current-stream recovery remain later increments.

### Plex playlists

Choose a music library, then open the **Playlists** tab. The picker lists audio playlists on that library's server, including playlists that contain tracks from other accessible music libraries on the same server. Lists are paged at 100 entries; opening a playlist requires a complete snapshot of at most 500 entries. Partial snapshots are not edited or partially inserted into the queue. Unknown or inaccessible track-source references remain visible and are explicitly unplayable.

To create a regular playlist, click a track title in **Tracks**, switch to **Playlists**, enter a title and choose **Create from selected track**. **Rename**, **Delete from Plex**, the entry arrows and **Remove** change the saved Plex playlist. These are explicit server writes and require Plex permissions. The Tracks row's **+ Playlist** saves to the loaded playlist; the target playlist and server are shown above the catalog. Appending is restricted to tracks on that playlist's server.

**Play playlist** replaces the listening session with the loaded ordered snapshot. **Play from here** snapshots the selected entry and the remaining playlist; earlier entries are not silently added to its repeat set or Previous path. **+ Queue** appends the complete snapshot without starting playback. Duplicate playlist entries become separate local queue occurrences. Subsequent server edits do not rewrite the listening session, and queue edits do not save back to Plex.

Regular playlist entries are moved/removed by Plex's `playlistItemID`, not the track rating key. Smart playlists, unknown smart capability, explicit read-only metadata and missing/ambiguous entry IDs disable editing. A normal playlist's editable appearance is a candidate capability, not proof that every permission is granted; the server still enforces authorization and denials are shown. The implementation never edits smart playlist filter rules.

Each existing-playlist write reads a complete fresh snapshot and compares a SHA-256 fingerprint of metadata and ordered entries with the UI's loaded revision. It sends one mutation, then reads back and verifies the requested result. A changed snapshot, ambiguous response, server failure or timeout requires **Refresh from Plex** and inspection before another write. Create verifies the returned playlist identity/title and initial track; it is not retried after an uncertain result. Request IDs are deduplicated for the latest 128 writes within the current backend/account context. Writes are serialized, stale account/view replies cannot repopulate a signed-out view, and writer commands carry the current account epoch.

Plex does not provide an atomic compare-and-swap in these endpoints. Read/compare/write/read-back catches observed changes but cannot eliminate every concurrent-client race. Pending edit outcomes are in-memory; after a backend crash, refresh and inspect Plex before making a new edit. Qoda never automatically replays an uncertain mutation. Signing out cannot retract a write that has already reached Plex; old replies are discarded locally. Playlist catalog/detail views are not durable offline caches.

API paths and source URIs follow the [official Plex Media Server API](https://developer.plex.tv/pms/). This increment's write flows are checked against a private HTTP fixture; the live owned-server check is read-only. Shared-server permissions, broader PMS compatibility and real production write qualification remain open acceptance work.

### Previous, shuffle and repeat

**Previous** restarts the selected track at zero when the local position is greater than three seconds. At three seconds or less it moves back through the Previous navigation path; without a prior entry it restarts the selected track. Repeated Previous actions move backward without appending duplicate navigation entries, and Next returns forward before continuing through ordinary upcoming content. Navigation preserves paused versus playing intent. Offline, Previous/Next update the local selection without fetching media; restore sign-in to resume audio.

Only a fresh, positive nominal audio clock from the current engine generation adds an ordinary selection to the Previous path. Browsing, preparation, paused loads and manually skipped selections do not. Navigating through the path does not fabricate a new historical entry. Choosing another queued occurrence while navigating creates a new forward branch once nominal presentation is observed. The path is navigation state, not a complete playback/listening-history archive or physical-output guarantee. This increment retains the latest 4096 navigation entries and displays an indication if older entries were dropped. The queue panel's **Previous path** tab exposes this retained route in pages of 50 entries, in chronological route order. **Older** and **Newer** browse without selecting tracks; **Follow latest** returns to the latest page and follows new route entries. **Go here** selects that exact path entry at zero, preserving paused/playing intent, and Next returns through the retained forward route. Repeated appearances of the same occurrence remain distinguishable by route position. Requests carry the session, queue revision, route index and occurrence identity; stale or mismatched rows are rejected before speculative output is cancelled. Removing entries or branching can shorten the path; this inspector does not preserve deleted branches, timestamps, listening durations or physical-output claims. A complete listening-history archive remains separate work.

**Shuffle** materializes an upcoming order once. Rerendering, metadata refreshes, Next, repeat cycles and restarts do not reshuffle it. The selected entry, consumed order and forward Previous path stay fixed. Add to queue remains a literal append. Play next remains FIFO ahead of ordinary upcoming entries. Moves/removals/insertions update the normal order as well as the visible order; disabling shuffle restores remaining normal order with those edits. Selected and forward Previous-route entries are pinned; ordinary upcoming entries remain editable.

Drag handles now support [identity-fenced queue and playlist reordering](reordering.md), alongside the existing keyboard move buttons. Pinned queue entries and read-only/smart/busy/uncertain playlist edits remain restricted; no order is changed optimistically.

**Repeat** cycles through Off, One and All. One repeats the selected occurrence only after matched natural completion; manual Next bypasses it. All cycles through retained session membership in its established effective order, without redrawing shuffle. Removed or cleared upcoming occurrences cannot return through repeat. Playback/preparation errors stop rather than repeatedly retrying. Automatic repeat also stops with a visible error when the completed native visit had no qualified positive nominal clock; this avoids silently spinning on an empty or unconfirmed source. Very short or unqualified-clock content may therefore require explicit replay.

Shuffle/repeat settings are explicit and survive Play now, Stop & clear and disconnect; those actions still discard the appropriate session/navigation data. Modes, effective order and Previous cursor are checkpointed and restore paused. The migration from schema/payload 1 to 2 creates a consistent pre-migration backup and updates the checkpoint transactionally. It preserves old queue identity/order/position but starts an empty Previous path, because older checkpoints did not record presentation evidence. Future unsupported versions are refused.

### Durable sessions and recovery

Session data lives in `$XDG_STATE_HOME/qoda/session.sqlite3` (default `~/.local/state/qoda/session.sqlite3`). The directory is owner-only (0700); database and backup files use 0600. The backend is the only application writer. SQLite uses transactions with FULL synchronous mode on a separate worker thread, so checkpoint I/O does not block playback controls. Initial schema creation and the 1-to-2 migration are transactional; newer schema or payload versions are refused without modification.

The checkpoint includes full retained occurrence membership, normal/effective order, duplicate identities, selected occurrence, pending Play next priority, prepared Plex media/part version IDs, nominal local position, completion state, shuffle/repeat modes and the Previous path/cursor. Runtime playing intent, tokens, key material, media URLs and HTTP grants are excluded. The already implemented session state is restored; individual unavailable-entry reasons are retained as typed local state. A complete listening-history archive remains separate work. Display labels in queue records are retained session metadata, not a complete offline catalog.

Queue changes are scheduled promptly; position checkpoints target five seconds, with writes also requested on pause, seek, track change and orderly exit. The storage message distinguishes Saving, Saved, Unsaved and blocked recovery. In-memory acceptance is not a durability acknowledgment. Failed writes retain the previous valid checkpoint and leave controls usable. **Retry save** retries the current coherent in-memory session after a write failure. A failed initial load remains blocked until restart or offline recovery; it cannot later overwrite recovered data with a default empty in-memory session. There is no maximum-loss promise while writes are failing or delayed.

Startup restores metadata and position while remaining paused. It does not restore signed stream access or contact Plex. Restore sign-in explicitly, then choose Resume to prepare fresh access for the retained source-scoped track and version. The saved local position is applied using a per-file libmpv start option before unpause. Seeking rebuilds the selected stream at the target and preserves paused intent; this can introduce a gap. A changed prepared media/part version stops with a visible error instead of silently substituting it. These provider IDs are not a content hash or a hardware timing guarantee.

A consistent SQLite backup is made at most daily when a nonempty session is saved, keeping the latest three under `backups/`. A backup failure is reported separately from a successful current checkpoint. Original databases preserved during explicit recovery remain available until account cleanup; they are not silently pruned as daily backups. There is no byte-copy backup of an open database.

Damaged durable data is preserved and blocks automatic replacement with an empty session. To recover, stop Qoda and run:

```sh
./tools/dev.py --restore-backup
```

This validates the latest backup, restores a consistent copy and preserves the original as `session-preserved-<uuid>.sqlite3`. Recovery requires exclusive backend ownership and also refuses newer unsupported data. An interrupted recovery is detected and is not treated as a new empty installation. Start Qoda normally afterward; playback remains paused. If the latest backup is unusable or storage permissions prevent recovery, the command leaves the original available for manual recovery; it does not silently try older data.

Disconnect/sign-out schedules removal of the saved session, daily backups and preserved/partial recovery copies. A failed cleanup is explicitly incomplete and can be retried; it is not reported as successful merely because keyring removal succeeded. This removes app-owned files and logical SQLite content, not a forensic-erasure guarantee. Credentials remain governed by the separate Save/Restore/Forget controls.

The implementation uses the [rusqlite backup API](https://docs.rs/rusqlite/0.41.0/rusqlite/backup/index.html) and [SQLite transaction durability controls](https://www.sqlite.org/pragma.html#pragma_synchronous). No metadata cache or artwork database is introduced in this increment.

### Saved sign-in

After connecting, choose **Save sign-in**. Qoda stores a versioned credential in the desktop keyring and reads it back to verify the write. On a later launch, choose **Restore saved sign-in**. Startup does not inspect or unlock the keyring automatically, load a track or play music. Explicit keyring actions may show the desktop unlock prompt.

**Disconnect** stops playback and clears the active account and queue from memory while keeping the saved sign-in. **Sign out & forget** also removes Qoda's saved sign-in. Only items matching `application=qoda-player`, `credential=plex`, `schema=1` are touched. Saving replaces Qoda's previous saved account. Forget does not revoke the Plex token remotely or remove credentials belonging to other apps or the validation helper.

A single worker serializes keyring side effects: a pending Save completes before a later Forget. Restore results are fenced by the current authentication generation so disconnecting or beginning another login cannot resurrect an old restore. Forget checks for matching items afterward and reports incomplete removal if locked items remain. Helpers have bounded input/output and a 30-second limit per invocation; failure or timeout leaves saved state explicitly unknown until retried. Credentials use private pipes and zeroizing buffers, with controlled error messages.

The helper behavior follows the [upstream libsecret tool](https://github.com/GNOME/libsecret/blob/main/tool/secret-tool.c) and [Secret Service APIs](https://gnome.pages.gitlab.gnome.org/libsecret/). App startup never invokes the helper; all three actions are explicit.

The window's **Hide** button and compositor close request hide the interface. Playback belongs to the Rust process. To show it again:

```sh
quickshell ipc --path ./ui call -- control show
```

The foreground launcher attempts to restart an exited UI up to three times while retaining the backend. QML reloads and separately started replacement windows reconnect to the same state. **Quit** stops the backend; Ctrl+C stops processes started by that launcher. A second launcher shows the existing window. To stop the backend from another terminal:

```sh
./tools/dev.py --quit
```

For this machine's previously authorized validation account, an explicit development option reuses its existing Secret Service credential in memory:

```sh
./tools/dev.py --use-validation-login
```

That import reads only `application=qoda-plex-legacy-validation`, passes the decoded credential over a private stdin pipe and does not copy it into application configuration. It does not alter or delete the validation item. Missing or locked credentials can require an explicit sign-in instead. Do not put Plex tokens in command arguments, environment variables or committed files.

The backend can run separately with `./tools/dev.py --backend-only`; start a replacement interface with `quickshell --path ./ui --no-duplicate`. `--credential-stdin` on the backend accepts a bounded JSON credential from a private pipe for development; normal sign-in does not require it.

## Implemented boundaries

- The backend uses an owner-only runtime directory and socket, a process lock and same-user peer checks. Protocol 1 requires a hello and an instance identifier for subsequent commands. Revisions and provider offsets use decimal strings. Snapshots carry display metadata and source-scoped track references, never Plex credentials or upstream media URLs.
- Catalog and media preparation run outside the coordinator. Superseded browse/preparation requests are cancelled; generation checks reject stale completions. Disconnect cancels active work and revokes media access.
- libmpv receives a revocable, unguessable loopback media grant. The backend authenticates HTTPS requests to Plex, refuses HTTP redirects and streams validated single byte ranges. Tokens remain in the HTTP layer. The proxy supports GET/HEAD and only exposes necessary media headers.
- Playback defaults to Desktop/PipeWire with Auto ReplayGain. Explicit Fidelity output is available under Menu → Audio settings; see [direct ALSA implementation and qualification limits](audio/direct-alsa.md). Menu → Audio settings selects Off/Track/Album/Auto; the initial metadata reader supports native FLAC tags and reports unity fallback for unavailable gain metadata. See [ReplayGain scope and measurements](audio/replaygain.md). The displayed position is a nominal libmpv audio clock, not a hardware presentation or listening-history guarantee. The displayed selected track is not used as a claim that its samples have reached the output.
- Only nonsecret source identity mappings are persisted in `$XDG_CONFIG_HOME/qoda/source-identities.json` (default `~/.config/qoda/`), using an atomic replacement with mode 0600. The queue and nominal position are checkpointed separately in the session database. Sign-in is saved only when requested, in Secret Service rather than application files. Startup stays paused and does not load music.

## Gapless chaining

Gapless defaults On for each backend session; the header control can disable it. This preference is not persisted. After a fresh positive clock confirms the current occurrence, the coordinator prepares at most one speculative successor through the provider and grants it a second private media URL. libmpv uses `gapless-audio=weak` and playlist prefetch, allowing compatible files to chain without stopping/reloading at the boundary. Weak mode permits output reconfiguration when formats differ; it does not force later tracks into the first track's output format. See the [mpv gapless options](https://mpv.io/manual/master/#options-gapless-audio). Demuxer buffers are bounded to 32 MiB forward and 8 MiB backward per demuxer; preparation has a 20-second timeout.

Stable native playlist-entry IDs and a matched natural predecessor EOF bind the handoff to the exact queue occurrence and prepared version. Selection can move before nominal presentation. Only an owner-bracketed, fresh positive audio clock confirms nominal presentation; negative or missing clocks remain unknown. A very short successor that finishes between observations is consumed once without inventing listening credit or replaying it. Existing unconfirmed-repeat guards remain in force.

Queue and transport mutations cancel speculative work before applying the change. The native thread acknowledges either that the future was removed while the current entry retained ownership, or that a decoder handoff already occurred. A late handoff requires a stop/reset barrier and leaves playback paused with a review message, because earlier presentation is uncertain. Stale queue revisions are rejected. Each proxy grant is revocable; a failed speculative stream cannot mark the current stream failed before promotion. Preparation failures leave the current track running and use normal loading at its end. Short tracks, slow preparation, format changes and unavailable timing witnesses can still produce gaps or require review.
